# Server Pulse Tauri 跨平台移植方案（简易版）

本文档是"基于 Tauri 把 Server Pulse 重写为跨平台桌面应用"的简易方案，面向决策与规划，技术细节从简。深入设计在正式开工时另行细化。

## 1. 背景与目标

当前 Server Pulse 是 Windows 专属应用（PowerShell 5.1 + WPF），无法在 macOS 上运行。目标是用 Tauri 2 重写一套跨平台版本，**同一份代码同时支持 Windows 和 macOS**，功能与现有版本对齐：

- 多台 SSH 服务器实时监控（GPU / 显存 / CPU / 内存 / 用户归属）；
- 独立置顶透明浮窗、托盘、贴边隐藏；
- 历史记录、曲线查询、保留策略与数据迁移；
- 服务器端常驻监控代理的注入、控制与记录合并。

## 2. 技术选型

| 决策项 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | Tauri 2 | 体积小（安装包约 5–15 MB）、内存占用低，适合"常驻浮窗"形态；官方支持 Windows / macOS / Linux |
| 后端语言 | Rust | Tauri 固定后端语言，负责 SSH、文件、进程等平台能力 |
| 前端 | Web 技术（React / Vue / Svelte 任选，开工前定） | 渲染在系统 WebView 内，用户看到的是独立桌面窗口，无需浏览器 |
| 排除 SwiftUI | — | 仅支持 Apple 平台，不满足跨平台目标 |
| 排除 Electron | — | 体积大、内存高，与"轻量常驻浮窗"定位不符（备选，团队若更熟 JS 可再议） |

## 3. 整体架构

```
┌─────────────────────────────────────────────┐
│  前端（WebView 内渲染）                       │
│  主浮窗 / 服务器管理 / 历史曲线 / 主题语言      │
├─────────────────────────────────────────────┤
│  Tauri 桥接层（IPC）                         │
├─────────────────────────────────────────────┤
│  Rust 平台层（Windows / macOS 双实现）        │
│  SSH 会话 · 凭据存储 · 数据目录 · 窗口能力     │
├─────────────────────────────────────────────┤
│  核心逻辑层（平台无关，可移植自现有代码）        │
│  采集协议 · 指标解析 · 历史格式 · 服务器端代理  │
└─────────────────────────────────────────────┘
```

原则：**核心逻辑层尽量复用现有实现，平台层全新编写**。

## 4. 复用与重写清单

| 现有模块（PowerShell） | 处理方式 | 说明 |
| --- | --- | --- |
| `ServerPulse.Sample.ps1` 采样脚本 | ✅ 直接复用 | 运行在 Linux 服务器端，与客户端平台无关，这是核心资产 |
| 服务器端 Agent（`~/.serverpulse/`） | ✅ 直接复用 | 注入、启停、状态检测、记录合并逻辑照搬 |
| 历史格式（JSON / JSONL）与合并规则 | ✅ 复用格式 | 纯文本格式，任何语言可读写；macOS 端沿用，可与 Windows 端共享数据 |
| 指标解析、退避熔断、指纹校验逻辑 | 🔄 移植 | 逻辑不变，改写为 Rust |
| WPF 界面（`ServerPulse.ps1` + XAML） | ❌ 重写 | 换成 Web 前端 + Tauri 窗口 API |
| 窗口行为（置顶 / 透明 / 贴边 / 托盘） | ❌ 重写 | Tauri 原生窗口能力 + 自定义实现（macOS 无系统级贴边，需自行实现） |
| Windows 凭据管理器（`advapi32`） | ❌ 替换 | macOS 用 Keychain（钥匙串） |
| EXE 宿主（`ServerPulse.Host.cs`） | ❌ 替换 | macOS 用系统 .app 包结构，无需 Job Object 等 Win32 机制 |
| 数据目录 `%LOCALAPPDATA%` | ❌ 替换 | macOS 用 `~/Library/Application Support/ServerPulse/` |
| SSH 路径 `ssh.exe` | ❌ 适配 | macOS 用系统 `/usr/bin/ssh` |

## 5. 开发环境与构建

- **日常开发在 Windows**：前端调试、Rust 逻辑、单元测试全部在 Windows 完成；Windows 版可本地直接运行验证。
- **macOS 产物由云端构建**：使用 GitHub Actions 的 macOS runner（如 `macos-15`）编译 `.app` / `.dmg`。
- **成本为零的前提**：仓库设为 **public**——GitHub Actions 对公开仓库的 macOS runner 免费；私有仓库的 macOS 分钟按 10 倍计费，免费额度仅约 200 分钟。
- 使用官方 `tauri-action` 工作流，一条命令即可同时构建 Windows + macOS 产物并自动发布。

## 6. 分发方案

- 产物发布到 **GitHub Releases**，同时提供 `.dmg` 与 `.app.zip` 两种格式。
- **暂不购买 Apple Developer 账号（$99/年）**，产物为未签名（ad-hoc）状态：
  - 可以正常运行，但首次打开需"右键 → 打开"确认，或终端执行 `xattr -dr com.apple.quarantine <App>`；
  - 通过 AirDrop / U 盘分发可跳过该步骤；
  - 不影响个人使用与朋友间分发。
- **将来正式公开分发时**再购买开发者账号，补齐签名与公证（notarization），实现"双击即开、零警告"。

| 阶段 | 内容 | 验收标准 |

## 8. 风险与注意事项

- **Rust 学习成本**：团队为 PowerShell / .NET 背景，需预留学习时间；若阻力过大，可退而评估 Electron（JS 生态，SSH 库现成）。
- **透明浮窗**：Tauri 2 在 macOS 上支持透明窗口，但存在个别细节限制，需要实际验证。
- **贴边隐藏**：macOS 无 Windows 式系统级贴边，需自行监听窗口位置实现，工作量与现在 Windows 版相当。
- **未签名应用的体验**：分发前需在 README 写明"首次打开"操作说明。
- **CI 免费额度依赖 public 仓库**：若仓库转私有，macOS 构建会产生费用。
- **历史数据兼容**：macOS 端沿用现有 JSONL 格式，但数据目录不同，跨平台迁移需提供导入路径（可复用现有迁移交互）。

## 9. 待定决策（开工前确认）

1. 前端框架：React / Vue / Svelte 选哪个（取决于团队熟悉度）；
2. SSH 实现：直接调用系统 `ssh` 命令（移植现有设计最快），还是用 Rust 库（如 `russh`）内嵌实现；
3. 是否保留"先做 M1 核心抽取、后做 UI"的顺序（推荐，核心逻辑是项目价值所在）。
